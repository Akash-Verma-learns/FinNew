Data Landscape

What's Inside a Financial Report

One filing contains hundreds of data points — time-segregated, segment-nested, and often contradictory across sources.

Document Types (Time-Segregated)
10-K  Annual ~200 pages
Full-year audited financials, MD&A, risk factors, forward guidance, auditor sign-off. Highest reliability.
10-Q  Quarterly ~80 pages
Unaudited interim numbers, YoY comparisons, updated guidance. Higher revision risk.
8-K  Event-Driven ~5 pages
Material events: earnings releases, M&A, executive changes. Claims often unverified at time of filing.
Earnings Call PDF  Transcript
Forward-looking statements, segment color, analyst Q&A. Highest risk of unverifiable claims.

⚠ The Challenge
"Azure revenue grew 21%" can be reported in the 10-K, the 8-K press release, and the earnings call — often with slightly different numbers due to FX adjustments, reclassifications, or different time periods. FinValidator reconciles these against the XBRL-tagged filing.
Verification Architecture

Finding the Single Source of Truth

Not all data sources are equal. FinValidator uses a strict priority hierarchy to resolve conflicts.

Priority Hierarchy
1
SEC EDGAR XBRL (company-reported)
Machine-readable tags from the actual 10-K/10-Q filing. These are auditor-signed numbers, submitted directly to the SEC under penalty of law. Our ground truth.
2
FASB Calculation Linkbase (derived)
Standard accounting relationships (GrossProfit = Revenue − COGS). Used when a derived metric isn't explicitly reported but can be computed from reported values via the FormulaGraph.
3
Tavily Web Search + LLM Reasoning
For non-XBRL claims (guidance, qualitative statements, recent events). Cross-references SEC.gov, BusinessWire, Yahoo Finance. Lowest confidence tier.
FormulaGraph — Derived Metrics
ROE       = NetIncome ÷ Equity × 100
FCF       = OperatingCashFlow − CapEx
FCFMargin = FCF ÷ Revenue × 100
ROIC      = NOPAT ÷ InvestedCapital × 100
MACD      = EMA(12) − EMA(26)
Grounding Pass — Handling Unverifiable Claims
Claim Extracted
"Azure revenue grew 29% in FY2024"
XBRL Lookup
Query EDGAR for MSFT segment revenue FY2024 Q4. If found → VERIFIED.
RAG Fallback
Check ingested 10-K text chunks via vector similarity. Segment-specific numbers often buried here.
Grounding Pass ← New
Claims still UNVERIFIABLE get a second pass: Tavily web search → LLM re-reasons with fresh citations. Most resolve to PARTIALLY_VERIFIED (conf ~0.68).
Final Verdict
VERIFIED / PARTIALLY_VERIFIED / CONTRADICTED / UNVERIFIABLE + confidence 0–1
Core Engine

The 7-Step Validation Pipeline

Each claim runs through every step independently and in parallel — a single report with 30 claims takes ~2 minutes end-to-end.

1
Claim Extraction
LLM reads each section and outputs typed claims: {type: "revenue", ticker: "MSFT", value: 61.9, unit: "B", period: "FY24"}
2
XBRL Direct Lookup
Query SEC EDGAR XBRL API for the exact concept (us-gaap:Revenues) for the reported period. Strongest possible match.
3
FormulaGraph Derivation
If direct concept not found, compute it from parent concepts via the pre-built directed acyclic formula graph.
4
Non-GAAP Reconciliation
Detect adjusted/non-GAAP metrics (Adjusted EPS, Organic Revenue) and flag reconciliation gaps vs. GAAP equivalents.
5
RAG Vector Search
Semantic search over ingested 10-K text chunks. Catches narrative claims, segment color, and guidance language.
6
Web Search (Tavily)
Live search across SEC.gov, BusinessWire, Yahoo Finance. LLM reasons over returned citations to produce a confidence score.
7
Grounding Pass New
UNVERIFIABLE claims re-enter the pipeline with broader search queries. Recovers ~60% of initially unverifiable claims.
Output per Claim
VERIFIED PARTIALLY_VERIFIED UNVERIFIABLE CONTRADICTED ERROR
+ confidence 0.0–1.0  ·  citations[]  ·  reasoning text  ·  severity flag (HIGH/MEDIUM/LOW)
